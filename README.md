# DocuChat AI — RAG Document Assistant

A full-stack **Retrieval-Augmented Generation (RAG)** chatbot. Upload a PDF, DOCX, PPTX, or TXT file and ask natural-language questions about it. Instead of stuffing the whole document into the prompt, DocuChat **chunks** your document, **embeds** each chunk into a vector, and at query time **retrieves only the most relevant pieces** via vector search before answering with Groq — so answers stay accurate and the system scales to large documents.

## ✨ Features

- **Multi-format upload** — PDF, DOCX, PPTX, and TXT (up to 10 MB).
- **True RAG pipeline** — Documents are chunked, embedded (Jina), and indexed in MongoDB Atlas Vector Search. Questions retrieve only the most relevant chunks.
- **Grounded answers** — Responses are generated by Groq using *only* the retrieved context, reducing hallucination.
- **Clean plain-text responses** — No markdown tables, LaTeX, or noisy syntax — just readable paragraphs and bullet lists. A defensive cleanup pass also fixes character-duplication artifacts from some PDFs/PPTX.
- **Copy to clipboard** — Every response has a copy button that outputs clean text.
- **User auth** — Register, log in, and per-user document storage via MongoDB (bcrypt-hashed passwords).
- **Profile & settings** — Editable username, email, and avatar (stored locally). Toggle timestamps, auto-scroll, and compact mode.
- **Premium dark UI** — Modern dark theme with purple/pink gradients, glassmorphism, an animated welcome orb, and the Space Grotesk typeface.

## 🔁 How RAG Works Here

**Chunk → Embed → Retrieve → Generate**

1. **Upload** — The file is parsed by the matching extractor (pdfplumber / python-docx / python-pptx / text decoder) and cleaned of extraction artifacts.
2. **Chunk** — The text is split into overlapping, word-aware chunks.
3. **Embed** — Each chunk is converted to a 1024-dimension vector with Jina and stored in the `chunks` collection alongside its `document_id` and `user_id`.
4. **Retrieve** — When you ask a question, the question is embedded and MongoDB Atlas `$vectorSearch` returns the top-K most semantically similar chunks (scoped to your document).
5. **Generate** — Only those chunks are passed to Groq as context, which writes a grounded, plain-text answer. The Q&A is logged to the `responses` collection.

> The model never sees the whole document — only the most relevant parts for each question. That's what keeps answers accurate and lets it handle large files.

## ⚙️ Backend Setup

```bash
cd chatbot-backend

# Create and activate a virtualenv
python -m venv venv
.\venv\Scripts\Activate.ps1      # Windows PowerShell
# source venv/bin/activate       # macOS / Linux

# Install dependencies
pip install -r requirements.txt
```

Create a `.env` file inside `chatbot-backend/`:

```env
MONGO_URL=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/?retryWrites=true&w=majority
GROQ_API_KEY=gsk_your_groq_key_here
JINA_API_KEY=jina_your_jina_key_here
```

**Create the Atlas Vector Search index** (one-time). The helper script verifies your Jina key and creates the index automatically:

```bash
python scripts/setup_rag.py
```

This creates a vector index named **`vector_index`** on the `chunks` collection:

```json
{
  "fields": [
    { "type": "vector", "path": "embedding", "numDimensions": 1024, "similarity": "cosine" },
    { "type": "filter", "path": "document_id" },
    { "type": "filter", "path": "user_id" }
  ]
}
```

> You can also create this index manually in the Atlas UI → Atlas Search → Create Index → Vector Search.

Run the server:

```bash
uvicorn app.main:app --reload --port 8000
```

API is now at `http://localhost:8000`. Interactive docs at `http://localhost:8000/docs`.

## 🖥️ Frontend Setup

```bash
cd chatbot-frontend
npm install
npm run dev
```

The app opens at `http://localhost:5173`.

The frontend reads the backend URL from `VITE_API_URL`. Create `chatbot-frontend/.env`:

```env
VITE_API_URL=http://localhost:8000
```

> If `VITE_API_URL` is not set, the app falls back to the deployed Render backend URL.

## 🔌 API Endpoints

|---|---|---|
| `GET` | `/` | Health ping — returns `{status: running}` |
| `GET` | `/health` | MongoDB and Groq status |

| `POST` | `/login` | `{email, password}` — returns `user_id` + `username` |
| `POST` | `/upload/pdf` | Legacy alias — accepts any supported format |
| `POST` | `/upload/document` | Upload file (`file`, `user_id`, `document_name`) — chunks + embeds + indexes |
| `POST` | `/chat/ai` | `{user_id, document_id, message}` — embeds the question, retrieves chunks, answers |
| `GET` | `/chat/history/{user_id}` | Fetch all past Q&A for a user |

Supported upload formats: `.pdf`, `.docx`, `.pptx`, `.txt` (max 10 MB).

## 🛠️ Common Issues

**`ModuleNotFoundError: No module named 'pptx'`**
Your shell is using a different Python than the venv. Launch with the venv's Python directly:
```bash
.\venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

**`WinError 10013` (socket access forbidden) on startup**
Port 8000 is already in use by a leftover process. Kill it, or use another port:
```powershell
Get-NetTCPConnection -LocalPort 8000 | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
# or:  uvicorn app.main:app --reload --port 8001   (then set VITE_API_URL accordingly)
```

**`Vector search failed (is the 'vector_index' Atlas index created?)`**
Run `python scripts/setup_rag.py` and wait until the index status is **READY / queryable**.

**Old documents return no results**
Documents uploaded *before* RAG was enabled have no embeddings. Re-upload them so they get chunked and indexed.

**PowerShell cannot run `Activate.ps1`**
Run once per session:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

**Legacy `.doc` / `.ppt` files rejected**
These binary formats aren't supported — save as `.docx` / `.pptx` in Word/PowerPoint and retry.
